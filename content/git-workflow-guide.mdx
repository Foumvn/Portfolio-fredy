# Guide des Workflows Git : Du Chaos à la Clarté

Git est puissant, mais les équipes rencontrent souvent des difficultés faute d'accord sur quelques bases. Un workflow simple garde l'historique lisible, les revues ciblées et les releases moins stressantes.

Ce guide léger peut être adopté en un jour et amélioré plus tard.

## Un workflow d'équipe simple

- Créez une branche depuis `main` pour chaque changement.
- Gardez les branches petites et courtes.
- Ouvrez une pull request tôt et demandez une revue.
- Fusionnez dans `main` une fois les tests passés.

## Conseils pour les messages de commit

- Commencez par un verbe clair ("ajoute", "corrige", "supprime", "refactorise").
- Gardez la première ligne courte et spécifique.
- Préférez plusieurs petits commits plutôt qu'un seul énorme "WIP".

## Checklist PR

1. Expliquez ce qui a changé et pourquoi.
2. Liez l'issue ou décrivez l'impact utilisateur.
3. Ajoutez des tests (ou expliquez pourquoi pas).
4. Gardez le diff assez petit pour une revue rapide.

## Conclusion

L'objectif n'est pas un "Git parfait" — c'est moins de surprises et une collaboration plus rapide. Commencez simple, écrivez les règles, et améliorez-les à mesure que votre équipe grandit.
