# Bonnes Pratiques TypeScript pour un Code Propre et Maintenable

TypeScript brille quand il vous aide à modéliser la réalité — pas quand vous devez lutter contre les types toute la journée. Quelques bonnes habitudes rendent un codebase plus calme, plus sûr et plus facile à refactoriser.

## Règles pratiques

- Activez le mode strict et corrigez les angles morts tôt.
- Préférez les types lisibles aux types astucieux.
- Utilisez les unions pour "un parmi ceux-ci", les interfaces pour "la forme de ceci".
- Évitez `any` comme raccourci ; ça devient une dette future.

## Un pattern à mémoriser

```ts
type Result<T> =
  | { ok: true; value: T }
  | { ok: false; error: string };

export function parseNumber(input: string): Result<number> {
  const n = Number(input);
  return Number.isFinite(n) ? { ok: true, value: n } : { ok: false, error: "Ce n'est pas un nombre" };
}
```

## Conclusion

Le meilleur code TypeScript se lit comme une bonne documentation : des noms clairs, des formes prévisibles, et des erreurs qui pointent vers la solution.
